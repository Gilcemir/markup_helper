# ADR-001: Confidence-gated automatic injection with inline confirmation

## Status

Accepted

## Date

2026-05-27

## Context

Phase 3 injects four SciELO Publishing Schema (SPS 1.10) tags into JATS XML
that the SciELO Markup tool cannot produce. Two of the four values require
judgment, not just lookup:

- `data-availability` `@specific-use` — classifying a free-text statement into
  one of five categories.
- CRediT `<role>` — recognizing/normalizing written contribution terms and
  matching author initials to `<contrib>` elements.

The predecessor project (MathML, abandoned) failed because it demanded **manual
input for every value**, which was the same effort as marking by hand. The
core lesson: the friction was the manual data entry, not the placement logic.
Phase 3 must minimize human touch while not silently emitting wrong judgments.

The existing DocFormatter tool (phases 1/2) is fully non-interactive and emits
a per-file `.report.txt` and `.diagnostic.json`.

## Decision

Use a **confidence-gated automatic** workflow:

- Deterministic and high-confidence derivations are **applied automatically**
  without prompting (the `other` number from `other.txt`; editor name + role
  from the docx; an unambiguous data-availability classification; exact CRediT
  term matches).
- Only **genuinely ambiguous** judgment calls **pause for inline confirmation**
  in the terminal: the tool proposes a value and the human confirms or
  overrides before it is written.
- **Every** decision — including auto-applied ones — is recorded in the per-file
  `.report.txt`, so high-confidence auto-writes remain auditable after the fact.

## Alternatives Considered

### Alternative 1: Two-pass propose → review → apply (review queue)

- **Description**: Pass 1 runs the whole batch unattended and emits a review
  document per file (all proposed values + low-confidence flags); the human
  edits/approves it; pass 2 applies to the XML.
- **Pros**: Batch-friendly (review offline, not terminal-bound); fully
  auditable and re-runnable; cleanly separates computation from human judgment;
  closest to the existing "emit a report" convention.
- **Cons**: More moving parts (review-document format, state between passes);
  heavier than the user wants for the common case.
- **Why rejected**: User preferred the simpler inline model and accepted the
  terminal-bound trade-off; the confidence gate keeps prompts rare.

### Alternative 2: Single-pass fully interactive (inline, no gate)

- **Description**: Pause inline on every judgment call regardless of confidence.
- **Pros**: Simplest mental model; correction always in context.
- **Cons**: Re-creates MathML's friction by prompting even for clear cases;
  ties the user to the terminal for the entire batch.
- **Why rejected**: Defeats the central goal of reducing manual input.

## Consequences

### Positive

- Clear cases flow through with zero human input — directly addresses why
  MathML was abandoned.
- Ambiguous cases still get a human decision before being written, avoiding
  silently wrong XML.
- Reuses the existing per-file report convention for auditability.

### Negative

- Interactive prompts tie the operator to the terminal during a batch run
  whenever ambiguous cases occur.
- High-confidence auto-writes are not blocked, so a miscalibrated confidence
  threshold could auto-apply a wrong value.

### Risks

- **Miscalibrated confidence → silent error.** Mitigation: record every
  auto-applied decision in `.report.txt`; start with conservative thresholds
  that favor prompting; tune against the example corpus.
- **Prompt fatigue in large batches.** Mitigation: keep the gate tight so only
  truly ambiguous cases prompt; revisit a batch review mode if prompts prove
  frequent.

## Implementation Notes

Confidence thresholds and the exact "ambiguous" criteria per tag are a TechSpec
concern. The data-availability classifier can seed from the keyword corpus in
`docs/scielo_context/jats/data_availability.md`.
