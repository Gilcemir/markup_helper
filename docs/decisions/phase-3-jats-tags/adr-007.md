# ADR-007: Free-text role fallback as an operator-chosen, document-scoped disposition

## Status

Proposed

## Date

2026-05-27

## Context

ADR-005 auto-applies CRediT `<role>` only when a statement is structured and
**every** term exact-matches the table and **every** author resolves uniquely;
anything else is gated to the `IConfirmer` (ADR-006), and the injector emits
only the "clean" per-author subset. Reviewing a real corpus document
(`1984-7033-cbab-26-02-e54582628`, docx 5458) exposed a gap.

Its CREDIT statement is role-keyed but mixes three failure modes:

```
Conceptualization: Nascimento AR, Neto VBP, Costa AES, Ishikawa FH;
Supervision: Ishikawa FH, Neto VBP, Costa AES;
Methodology and Molecular data analysis: Nascimento AR, Ishikawa FH;
Investigation: Nascimento AR, Borel JC, Araújo KMG;
Writing and Review: Nascimento AR, Ishikawa FH.
```

- `Molecular data analysis` is **not** a CRediT term — a genuine custom role.
- `Writing and Review` is a **misspelling** of `Writing – review & editing`,
  not a custom taxonomy.
- `Neto VBP` resolves to `NotFound` because "Neto" is the JATS `<suffix>`, not
  the `<surname>` (`<surname>Paiva</surname><suffix>Neto</suffix>`).

Today the injector emits only the three fully-clean authors (Costa, Borel,
Araújo) and **silently drops** Nascimento, Ishikawa and Neto — losing their
valid contributions (Conceptualization, Investigation, Supervision) because the
per-author rule is all-or-nothing.

The curated spec (`docs/scielo_context/jats/credit_roles.md`) is explicit that
custom roles are allowed — as free text **without** `@content-type` — and that
the CRediT all-or-nothing is **per document**: either every `<role>` carries
`@content-type` or none does. The tool has **no code path** to emit a free-text
role: `CreditRolesInjector` only builds roles via `CreditTermTable.TryMap`, and
every `CreditRole` carries a `ContentTypeUrl`. So a document that legitimately
uses a custom taxonomy cannot be represented at all.

Crucially, the tool **cannot** distinguish "operator used a custom taxonomy"
(`Molecular data analysis`) from "operator made a typo of a CRediT term"
(`Writing and Review`). These demand opposite actions (free-text vs. normalize),
and choosing between them is exactly the human judgment ADR-001/ADR-005 route to
a prompt.

## Decision

Add a **document-scoped free-text disposition** to the CRediT confirmation flow,
chosen by the operator — never auto-selected.

- When any term is unrecognized or any author is unresolved, the credit-roles
  tag is already gated to a single `IConfirmer.Confirm` call. Extend that gate
  with a third outcome alongside override-the-term and skip:
  **"emit the document as free text"**. Selecting it makes the injector write a
  `<role>` for **every** author/term in the statement **without**
  `@content-type` — honoring the SPS per-document all-or-nothing.
- This is **operator-chosen**. The tool must not auto-decide free-text, because
  it cannot tell a custom role from a misspelled CRediT term, and auto-emitting
  free text would convert a one-character typo into permanent loss of structured
  CRediT for the whole document.
- **Non-interactive policies stay conservative.** `--non-interactive=accept`
  does **not** select free-text; it keeps the current "clean CRediT subset"
  behavior (or, preferably, abstains and flags the document for review).
  `--non-interactive=fail` surfaces the document as ambiguous, as today.
- Every disposition — clean subset, free-text-document, or skip — is recorded in
  the per-file `.report.txt`/`.diagnostic.json` (ADR-001 auditability).

This **amends ADR-005** (the unrecognized-term branch gains a spec-faithful
free-text target instead of only partial-or-skip) and **extends ADR-006** (the
`IConfirmer` contract gains a document-scoped free-text outcome, e.g. a new
`ConfirmDisposition.FreeText`, beyond value/override/skip).

## Alternatives Considered

### Alternative 1: Automatic free-text fallback on any unmapped term

- **Description**: Whenever a term fails to map, silently emit the whole
  document's roles as free text without `@content-type`.
- **Pros**: Zero prompts; maximum completeness; always spec-conformant on the
  per-document uniformity rule.
- **Cons**: Cannot distinguish a typo from a custom role, so a misspelling like
  `Writing and Review` would strip structured CRediT from an entire document
  that a one-token normalization would have kept fully CRediT — the common case.
- **Why rejected**: Violates "prompt rather than guess" (ADR-001/005) and
  optimizes the rare case (real custom taxonomy) at the expense of the common
  one (sloppy spelling).

### Alternative 2: Per-author free-text (mixed document)

- **Description**: Emit the unmatched author's roles as free text while keeping
  the matched authors' roles CRediT-typed.
- **Pros**: Local; preserves the most structure.
- **Cons**: Produces a document with some `@role` carrying `@content-type` and
  some not — exactly what the SPS per-document all-or-nothing forbids.
- **Why rejected**: Non-conformant XML.

### Alternative 3: Status quo (drop unmatched, keep partial CRediT)

- **Description**: Keep emitting only the clean per-author subset.
- **Pros**: No contract changes.
- **Cons**: Silent loss of real contributions (the observed e54582628 case);
  no way to represent a legitimately custom taxonomy.
- **Why rejected**: Silent data loss is the failure mode this ADR exists to fix.

## Consequences

### Positive

- Documents with a genuine custom taxonomy become representable, spec-faithfully
  (free text, no `@content-type`, uniform per document).
- Eliminates silent loss of valid contributions: the operator makes an explicit,
  audited choice instead of the tool dropping authors.
- Keeps the high-precision auto path for clean structured statements untouched.

### Negative

- Adds a third branch to the CRediT prompt, slightly more decision load for the
  operator on ambiguous documents.
- `IConfirmer`/`ConfirmResult` contract change ripples to all three policies and
  their tests.

### Risks

- **Operator over-uses free-text instead of normalizing a typo**, downgrading
  documents that should stay CRediT. Mitigation: the prompt must surface *which*
  terms failed and *why*, and offer normalization (override) as the first
  option; record the chosen disposition in the report for audit.
- **`accept` mode still drops data** by emitting only the clean subset.
  Mitigation: prefer abstain-and-flag over silent partial in `accept`; revisit
  once the interactive path lands.

## Implementation Notes

- `CreditRolesInjector.Apply` already issues a single `Confirm` for the
  unrecognized/unresolved branch — the natural place to interpret a new
  `ConfirmDisposition.FreeText`. On that disposition, emit `<role>` (no
  `@content-type`) for every parsed author/term across the document.
- Adjacent issues observed in the same document are **out of scope** for this
  ADR but should be tracked separately: (a) `CreditStatementParser` does not
  split a composite label like `Methodology and Molecular data analysis` on
  "and", so the valid `Methodology` inside it is lost; (b)
  `AuthorInitialsResolver.SurnameMatches` ignores `<suffix>`, causing
  Portuguese suffixes ("Neto", "Júnior", "Filho") to resolve as `NotFound`.
  Both are normalization/resolution fixes orthogonal to the free-text decision.
- Free-text mode is document-scoped: it must rewrite/replace any `@content-type`
  on roles it emits so the document is uniform.
